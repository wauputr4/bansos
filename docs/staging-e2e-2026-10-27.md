1. OAuth GitHub asli melalui Brave berhasil dengan scope profil `read:user`, tanpa scope repository/email.
2. Saat akun diperlakukan sebagai kontributor, akses admin ditolak 403. Form membuat usulan `uji-staging-oauth-20261027`; status pending dan listing belum dapat dibuka guest.
3. Setelah konfigurasi owner dikembalikan dan login ulang sebagai admin, judul usulan diedit lalu disetujui lewat UI. Guest langsung melihat listing D1 tanpa rebuild.
4. Komentar UI tercatat sebagai akun GitHub yang login. Teks `<b>...</b>` tampil literal, bukan HTML aktif.
5. Pemilik mengajukan revisi melalui dashboard. Judul publik tetap menggunakan versi approved sampai admin menyetujui revisi.

Ini menggunakan **satu identitas GitHub nyata**, dengan `OWNER_GITHUB_ID` staging sementara diubah antara bukan-owner dan owner. Ini bukan bukti isolasi dua identitas GitHub nyata. Konfigurasi akhir kembali ke owner sebenarnya.

Otomasi dialog konfirmasi hapus Brave sempat membuat dokumen browser tidak dapat dikendalikan. Pemilik menyelesaikan dialog secara manual. Pengujian mutasi berikut dilanjutkan melalui endpoint aplikasi, atas izin eksplisit; jangan menyebut semua dialog UI sudah lulus E2E.

## Uji API hosted dengan sesi sementara

Harness lokal `scripts/test-staging-api.mjs` dibatasi pada hostname, project, dan UUID D1 staging yang dikenal. Akun harus sudah tercipta lewat OAuth asli. Sesi acak maksimal sepuluh menit dibuat hanya untuk tes; SQL hanya dipakai untuk sesi dan pembacaan bukti. Semua perubahan konten melalui endpoint aplikasi dengan cookie sesi dan Origin yang sesuai. Token tidak dicetak, tidak membaca cookie browser, dan hash sesi tes dihapus pada blok `finally`.

Lulus sebagai kontributor:

- Akses admin ditolak; membatalkan revisi dan membuat revisi baru berjalan.
- Revisi belum approved tidak mengubah konten publik; versi stale ditolak 409.
- Identitas komentar palsu dalam payload diabaikan; identitas mengikuti sesi.
- Muatan `<script>` di-escape sebagai teks; tidak menghasilkan tag script yang dapat dijalankan.
- Komentar sendiri dapat dihapus secara recoverable.
- Arsip listing repo bukan miliknya ditolak; arsip listing sendiri menyembunyikannya dari guest dan membatalkan revisi pending.
- Pemulihan admin oleh non-admin ditolak 403.

Lulus sebagai admin:

- Memulihkan listing, menyetujui revisi baru, dan mengedit langsung berjalan.
- Persetujuan usulan withdrawn/stale dan persetujuan ulang ditolak 409.
- Hapus/pulihkan komentar, arsip/pulihkan listing, serta soft-delete/pulihkan listing berjalan melalui endpoint aplikasi.
- Setiap publikasi/revisi approved membuat event outbox; dua event tersimpan pending dengan nol percobaan karena Discord staging dimatikan.
- Sesi tes dibersihkan, termasuk setelah kegagalan assertion awal pada harness.

Assertion awal XSS terlalu ketat karena menuntut `&lt;script&gt;`, padahal output aman Svelte berbentuk `&lt;script>`. Assertion diperbaiki untuk menerima encoding aman itu sambil tetap menolak tag script mentah. Tidak ditemukan eksekusi script.
